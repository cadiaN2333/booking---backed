# 当前日期智能时段推荐设计

> 日期：2026-09-12
> 状态：已批准，待实施
> 范围：顾客端场地日历页的当前日期推荐，不包含跨场地或跨日期搜索。

## 1. 目标与边界

用户进入某个场地的日历页并选定日期后，可以通过快捷标签和可选的自然语言偏好获取最多三条推荐时段。推荐卡片位于日期选择工具栏下方，采用与现有“可约”状态一致的清爽绿色视觉体系。

推荐能力是只读辅助功能：它不能创建、确认、取消预约，也不能改动库存。推荐结果只表示查询时的可约快照；用户点击卡片后必须复用现有预约入口，由预约事务重新校验库存。

第一版明确不做跨场地搜索、未来多日搜索、聊天历史、用户画像、点击埋点或商家端推荐管理。

## 2. 已确认的交互

### 2.1 页面位置与样式

在 `booking-frontend/src/views/SlotCalendar.vue` 中，日期工具栏之后、原始时段网格之前新增推荐区域：

- 标题为“智能推荐时段”，标注“仅推荐当前日期的可约时段”。
- 提供四个可多选的快捷标签：`傍晚优先`、`尽早可约`、`余量充足`、`安静舒适`。
- 提供可选自然语言输入框，最长 300 个字符，例如“下班后想打球，人少一些”。
- 点击“为我推荐”后展示加载态；成功后展示最多三张绿色推荐卡。
- 每张卡展示开始/结束时间、价格、可约余量、匹配标签和简短理由；点击卡片复用原 `book(slot)` 流程。
- 当没有可约时段时展示空态；降级时展示“已按时间与可约余量为你排序”的非阻塞提示。

### 2.2 请求与响应

新增顾客端接口：`POST /api/recommendations/slots`。

请求字段：

| 字段 | 必填 | 约束 | 说明 |
|---|---:|---|---|
| `courtId` | 是 | 正整数 | 当前日历页的场地 ID |
| `date` | 是 | `yyyy-MM-dd` | 当前已选日期 |
| `query` | 否 | 最长 300 字符 | 用户自然语言偏好 |
| `tags` | 否 | 最多 4 个、仅允许已定义标签 | 快捷偏好标签 |
| `limit` | 否 | 1 至 3，默认 3 | 返回数量 |

响应字段：

| 字段 | 说明 |
|---|---|
| `recommendations` | 推荐结果列表，最多三条 |
| `slotId`、`courtId`、`startAt`、`endAt`、`price`、`available` | 预约跳转与库存快照 |
| `score`、`tags`、`reason` | 服务端评分、匹配标签与推荐理由 |
| `degraded` | `true` 表示未使用语义增强或模型理由，已回退到规则推荐 |

## 3. 混合式推荐流程

```text
当前场地 + 当前日期 + 偏好输入
        │
        ▼
SlotService 查询当前读模型
        │
        ▼
代码过滤 available > 0，生成唯一候选集
        │
        ├── 规则评分：标签、时间、余量、价格
        │
        ├── PgVector：仅按 courtId 元数据召回公开场地资料
        │
        └── ChatClient：仅为候选生成不超过两句的理由
        │
        ▼
服务端校验并返回候选集内的最多三条结果
```

硬约束由 Java 代码执行：只允许当前 `courtId` 和 `date`、只保留 `available > 0` 的时段、结果数量不超过请求上限。任何语义检索或模型输出均不得引入未知 `slotId`，也不得改变价格、余量和时间。

## 4. 规则、RAG 与模型职责

规则评分是推荐排序的基础，保证没有 AI 依赖时仍可用：

- `傍晚优先`：18:00 至 21:59 的开始时间加分。
- `尽早可约`：开始时间更早者加分。
- `余量充足`：`available` 较高者加分。
- `安静舒适` 与自然语言：仅作为 PgVector 公开资料的语义检索输入，不作为库存或价格判断依据。
- 同分时依次按开始时间、`slotId` 升序，确保响应稳定。

PgVector 查询只读取本场地的公开知识文档，元数据过滤条件为 `courtId`。检索内容只用于补充匹配标签和理由上下文，不能直接生成推荐时段。

ChatClient 只接收已筛出的候选摘要与检索到的公开资料，只能返回候选 ID 对应的简短理由。服务端在使用前验证 ID；若模型关闭、超时、返回非法内容或调用失败，保留规则排序并生成固定理由。

## 5. 配置、故障处理与安全

- 新增推荐功能开关，默认关闭，避免未配置聊天模型时阻断正常预约。
- 向量检索和聊天理由各自可独立启用；嵌入模型继续使用已配置的千问 OpenAI 兼容接口。
- 向量库、模型服务不可用、超时或返回无效结果时，接口返回 HTTP 业务成功、`degraded=true`，并以规则结果完成响应。
- 参数非法时返回现有统一参数错误；不向前端暴露模型密钥、提示词或内部异常栈。
- 不写入用户原始查询到 PgVector；日志仅记录场地、日期、是否降级、候选数和耗时。

## 6. 模块划分

后端在 `recommendation` 包内新增独立的请求/响应 DTO、候选构建器、规则排序器、语义增强器和编排服务；Controller 只做参数校验与返回。推荐服务通过 `SlotService` 获取时段，不直接访问 `SlotMapper`，不调用任何预约写服务。

前端新增推荐 API 类型与请求函数，并将日历页推荐区域拆为可测试的展示组件。卡片只调用日历页传入的选中回调，不复制预约逻辑。

## 7. 测试与验收

- 同一场地、同一日期仅返回 `available > 0` 的时段，且结果不超过三条。
- 不同日期或不同场地的时段绝不进入结果。
- 标签评分、同分排序和自然语言为空时的默认行为稳定可重复。
- 语义检索或聊天模型失败时仍返回规则候选，并将 `degraded` 标为 `true`。
- 模型返回未知候选时必须丢弃，不能返回伪造 `slotId`。
- 前端能提交标签与自然语言、显示加载/空态/降级态，点击推荐卡后使用现有预约确认弹窗。
- 后端 Maven 全量测试与前端生产构建均通过。
